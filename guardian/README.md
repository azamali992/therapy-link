# urduguard

A harm classifier you put in front of a chatbot, built and tested for how people in Pakistan actually write: English, Roman Urdu, Urdu script, and all three mixed in one message.

It ships three ways:

- a Python package: `urduguard.check(text, mode="strict")`
- an HTTP server with `POST /v1/moderations`, the same request and response shape as OpenAI's moderation endpoint, so a client swaps one URL, plus a richer native `POST /v1/guard`
- an int8 ONNX model directory with a coverage card: catch rate and false-alarm rate per language form with 95% intervals, the thresholds in use, and what was not tested

**Status: scaffold.** The package, server, data pipeline, evaluation harness and release gate run. The model directory behind the server today is a clearly labelled placeholder with a different label set. No catch rate or false-alarm rate has been measured for a v2 model yet. Read `models/*/coverage_card.json` before trusting any output; every response carries `model_hash`, `taxonomy_version` and `coverage` so you can check.

## Labels

`taxonomy_version = urduguard-2.0`. Multi-label.

| Label | Role |
|---|---|
| `violence_threats` | protective: gated |
| `harassment` | protective: gated |
| `hate_group` | protective: gated. Hate against a group by ethnicity, caste, gender, sexuality, nationality or disability. There is no religious-hate label and religious text is removed from every training and evaluation file by script. |
| `self_harm` | descriptive: reported, never gates a release |
| `sexual` | descriptive: reported, never gates a release |
| `needs_caution` | a flag, not a block: political, misinformation, borderline. Strict mode flags on it, loose mode does not. |
| `benign` | no label fired |

Why: `docs/research/01-taxonomy.md`.

## The requirement a release has to meet

For each Urdu form f (Roman Urdu, Urdu script, mixed) against English on the same items. R is catch rate on protective items, F is false-alarm rate on benign items. A rule is cleared only when the whole 95% interval is inside the limit.

| Rule | Condition |
|---|---|
| R1 catch-rate gap | R(EN) - R(f) <= 10 points |
| R2 floor | R(f) >= 70% |
| R3 false-alarm gap | F(f) - F(EN) <= 5 points |
| R4 no Urdu regression on update | [R_f(old) - R_f(new)] - [R_EN(old) - R_EN(new)] <= 5 points |
| R5 no harmful logs | the server stores no input text and no self_harm or needs_caution flags, by construction |

`python -m urduguard.eval.harness` computes R1 to R4 for any guardrail, not only this one. `python -m urduguard.eval.gate` is the CI gate (`.github/workflows/guardian-gate.yml`).

## Use

```bash
pip install -e ".[server]"
export URDUGUARD_MODEL_DIR=models/<model>
urduguard check "tum sab ko kal maar dunga"
urduguard serve --port 8000
curl -s localhost:8000/v1/moderations -H 'content-type: application/json' -d '{"input": "what a lovely day"}'
```

```python
import urduguard
urduguard.load("models/<model>")
r = urduguard.check("tum sab ko kal maar dunga", mode="strict")
r.flagged, r.labels, r.scores, r.form, r.coverage, r.model_hash
r.to_openai()   # the OpenAI results[] entry
```

## Privacy

The server never writes input text, results or flags anywhere. There is no setting that would. `GET /metrics` (off by default) returns counts only: requests, items, and flagged counts for the three protective labels. `self_harm` and `needs_caution` are never counted.

## Data

Training rows come only from sources licensed for a product (CC BY 4.0 so far: Aegis 2.0 train and validation prompts, IndicGuard Urdu train and valid prompts). The Aegis 2.0 test split and IndicGuard's test splits are the evaluation set: every prompt in them is hashed in `data/hashes/eval_exclusion.json` and `data/exclusion.py` refuses any training file that contains one. Religious content, sexual content involving minors and first-person self-harm disclosures are removed before any file is written; only counts survive. Every row carries `provenance` (source, split, licence, original label, where the labels came from, how the Urdu was produced). `data/MANIFEST.md` is generated by the build.

Roman Urdu in the current build is all transliterated from Urdu script by `data/translit.py` and tagged as such. Native Roman Urdu sources are listed in `docs/research/02-training-data.md` and are the next data task.
