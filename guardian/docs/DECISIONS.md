## 2026-10-21

1. **Repo.** The brief was opened from the recovery repo (D:\therapylink, branch rebuild/v2), but every v1 file it lists only exists in D:\therapylink-v3. Guardian v2 is built in D:\therapylink-v3 on branch `guardian-v2`. The recovery repo is untouched.
2. **Package name: `urduguard`.** `urduguard`, `guardian-urdu`, `urdu-guard` and `guardrail-urdu` were all free on PyPI on 2026-10-21 (404 on `/pypi/<name>/json`). `urduguard` is one word, imports cleanly (`import urduguard`), and says what it is. Nothing is published yet; the name is only reserved in `pyproject.toml`.
3. **Python environment.** D:\therapylink-v3 had no venv; the only one (D:\therapylink\ml\.venv) has CPU-only torch. A new venv was made at D:\therapylink-v3\ml\.venv with the CUDA 12.6 torch wheel plus the `requirements-local.txt` set, pip cache and temp on D:. Nothing was installed on C:. `HF_HOME=D:\dev\hf` for every run so model downloads stay off C:.
4. **Eval-split exclusion scope.** Hard rule 1 hashes every Aegis 2.0 *test* prompt. IndicGuard's `ur_test` rows are machine translations of the same prompts, so their English source column is also hashed where present, and the Urdu text itself is hashed too, so a row that arrives via IndicGuard is refused as well as one that arrives via Aegis.
5. **Religious filter.** Keyword list (Urdu script, Roman Urdu, English) plus any source category whose name contains religion/blasphemy. Applied in `guardian/data/filters.py` before a file is written to `guardian/data/build/`; counts go to the manifest, rows are dropped in memory.
6. **v1 audit scope.** The v1 files the brief lists under `ml/releases/guardian-v1c/` and `ml/registry.json` guardian entries do not exist in either repo: only `ml/releases/guardian-v1b/` exists, and the registry has no guardian entry. The audit says so and reports v1b.
7. **Research files 01 to 07** were drafted by parallel research agents under one rulebook (facts and tables, links, no app references, end in a decision) and reconciled by me. Three fixes: 07's gate table had invented R1 to R4 definitions and was rewritten to the brief's R1 to R5; 01 decided `needs_caution` is a flag and `benign` the empty set, so `taxonomy_version` is `urduguard-2.0` and the API exposes `needs_caution` as a flag, while the data files still carry `needs_caution` and `benign` as strings in `labels` because that is the simplest multi-label target; 02's call to drop IndicGuard `Culture_adaptive` rows is not followed: they are kept after the religion filter, since caste and gender hate rows are in scope. Numbers quoted in the research files came through web fetches and should be spot-checked before they go into the paper.
8. **Aegis 2.0 train contains 243 prompts whose text also appears in its test split under different ids** (short generic prompts). The build drops them (378 train rows and 18 val rows once IndicGuard's translations of the same prompts are counted) and the final files are checked again by `exclusion.py`. Hashing is by normalised text and by id, over Aegis test, IndicGuard English/test and Urdu/test (9,389 hashes, 2,964 ids).
9. **Out-of-scope rows are dropped from training, not relabelled benign.** Aegis rows whose only categories are criminal planning, PII, drugs, profanity, fraud, malware, weapons, advice, copyright and similar (6,099 Aegis, 10,746 IndicGuard) are not what this model is for and must not be taught as benign. Guns/Illegal Weapons is out of scope too: acquiring a weapon is not a threat.
10. **Aegis responses are not used.** Only prompts. A guardrail sees the user turn first; response moderation is a later addition.
11. **Religious filter removed 5,368 of the source rows** (plus 601 transliterated rows the Roman Urdu spellings matched that the Urdu script had not). The list is broad on purpose and loses some benign rows. Minors filter: 394. First-person self-harm filter: 300 (these are un-redacted Reddit-style posts in Aegis; they are dropped so no annotator opens a file of personal disclosures; third-person and instructional self-harm content stays under the descriptive `self_harm` label).
12. **Roman Urdu is all transliterated** (`translit.py`, rule-v0, with spelling variants at 0.3 and code-mixing at 0.15 per word) from the IndicGuard Urdu rows. 16,788 train rows, every one tagged `urdu_from: transliterated` with the source text and the sampler seed. The research doc 02 names native Roman Urdu sources (RUT, PURUTT, RUHSOLD) that are not in this build yet; adding them is the first data task in NEXT.md.
13. **Form detector** is a word-list heuristic (`forms.py`) that needs three content words before it will call Latin text Roman Urdu. It is a placeholder for a trained char n-gram classifier. Its confusion matrix must ship in the coverage card.
14. **Architecture** (doc 04): primary is XLM-R base with LoRA r=8, exported to int8 ONNX; fallback mDeBERTa-v3-base; the XLM-R plus character-gate hybrid stays experimental until the perturbation test shows a gain; a char CNN from scratch and a fastText BiLSTM are ablation floors. The two smoke trainings in block 5 are the primary and the char CNN.
15. **Placeholder model.** The v1b release ONNX (278 MB, sha c95d94e9...) is not on this machine; the only crisis ONNX files on disk are two smoke bundles from 2026-10-03 (Multilingual-MiniLM, same 8-label head, same input signature). The one at `models/v1-crisis-placeholder/` is the 118 MB smoke bundle with the XLM-R tokenizer.json beside it. It is an untrained smoke model and scores about 0.5 on everything. It exists so the server, CLI and OpenAI-shape route run today; `config.json` and `coverage_card.json` say `placeholder: true` in three places and every response carries it. Only `suicidal`, `self_harm` (to `self_harm`) and `harm_to_others` (to `violence_threats`) are mapped; the rest of its labels are disclosures, not harms, and are dropped.
16. **Binary verdict for the gate.** The harness scores every system on one bit, "flagged": for systems whose taxonomy has no harassment label (Llama Guard 3, Qwen3Guard), an unsafe verdict with any category counts as flagged, so no system is penalised for naming harms differently. Per-label agreement is a separate table.
17. **Out-of-scope rows are not in the gate populations.** The harness keeps only rows that are protective (any of violence_threats, harassment, hate_group) or benign; needs_caution-only, self_harm-only and sexual-only rows are excluded from catch rate and false-alarm rate, as the brief defines them.
18. **Eval sampling keeps pairs.** `--limit` samples item ids (Aegis ids, shared by the English row and its IndicGuard Urdu and transliterated Roman Urdu rows), then takes every form of each sampled id, so the gap intervals are paired.
19. **CI gate runs a fixture backend**, 40 hand-written rows in four forms with a predictions file, because the runner has no GPU and no model. The baseline file is written by `gate.py --write-baseline` after a tag. Verdicts R1 to R3 are reported but ignored on the fixture (`--ignore-verdicts`) since n=6 per form cannot clear anything; the drop check is what fails the build.
20. **Qwen3Guard-Gen-0.6B is run with its chat template and greedy decoding on the RTX 2050 in fp16**, on 300 paired Aegis train items in en, ur and roman_ur. The run reads `data/build/train.jsonl`, never the test split.
21. **Smoke training set** is 2,000 rows drawn evenly over (form, first label) cells from the train build, dev is 600 rows the same way from val. Char CNN: 8 epochs on CPU. XLM-R: LoRA r=8, 300 steps at batch 16 on the GPU. Neither number means anything beyond "the pipeline runs".
22. **Qwen3Guard-Gen-0.6B run (block 4 proof).** 300 paired Aegis train items (891 rows: 91 to 98 protective and 195 to 211 benign per form), strict mode, 514 s on the RTX 2050 in fp16. English catch 93.4%, Urdu script 81.6%, transliterated Roman Urdu 34.4%; false alarms 23.6% / 42.2% / 32.5%. R1 and R3 not cleared for either Urdu form. The number is a harness proof on train items and transliterated Roman Urdu, not a paper result. Report in `runs/eval/qwen3guard-gen-0.6b-aegis-train/`.
23. **Smoke training results are recorded as they came out.** Char CNN (282k params, 8 epochs, 10 s): 21 to 28% catch at threshold 0.5. XLM-R LoRA r=8 at batch 16 ran one epoch of 1,891 rows (119 steps, 30 s, peak 2.4 GB on the 4 GB card, loss 0.478) and sits at the all-negative solution: 0% catch, 0% false alarm at 0.5. That is what a 30-second LoRA run on multi-label BCE does; it proves train, export (279 MB int8 ONNX) and the harness connect, nothing else. The `--steps 300` setting was longer than one epoch and the script stops at the epoch end; Kaggle runs use `--epochs`.
24. **Eval reports and train metadata are committed** under `runs/` (model weights, ONNX files and checkpoints are gitignored), so the repo shows what the harness produced without the 279 MB file.
