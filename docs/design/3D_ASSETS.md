# TherapyLink v3 3D assets (Jugnu)

Eve and the breathing object, built in Blender 4.5 LTS from Python scripts so they can be rebuilt or recoloured. Eve is a twisted jasmine/lotus bud with a hidden diya-flame core, floating over two faint ripple rings with a violet aura behind her. Breath is a flat, front-facing jasmine bloom that opens and closes inside a timer ring. It's meant to read as a tool, not a second Eve.

No lime anywhere. In the Jugnu system lime #89F336 means "a protection is on / saved on this phone" and nothing else, so the ripple rings, rim light, particles and the breath timer use violet #A36FFF and white-pink #FFD3EA.

## Animation clips

All motion is node transforms (rotation / scale / translation), no morph targets and no shader animation, so it plays in any glTF runtime. Every clip keys the same nodes, so switching or crossfading between clips never leaves a node stuck in the previous clip's pose. Last keyframe equals the first, so loops are seamless.

**eve.glb**

| Clip | Length | What moves |
|---|---|---|
| `idle` | 8.0 s | One slow breath per loop (7.5/min). Petals part slightly in a wave round the bud, Eve rises about 3 cm and grows 2%, aura and rings swell, the haze swirl sways. |
| `listening` | 4.0 s | Leans toward the viewer (~6°), petals held more open so the inner glow shows (this is how she reads "brighter"), core and aura scaled up ~15%, gentle pulse every 4 s. |
| `thinking` | 8.0 s | Outer petals turn 72° one way and inner petals 72° the other (5-fold symmetry, so the loop is invisible), the haze swirl turns 120°, slow circular wobble. Bud slightly closed. |

**breath.glb**

| Clip | Length | Phases |
|---|---|---|
| `box` | 16.0 s | 0–4 s inhale (petals unfold flat, flower and white-pink guide ring expand to the outer track) · 4–8 s hold open · 8–12 s exhale (petals fold back toward the viewer, ring contracts) · 12–16 s hold closed. Sine ease in/out on each phase. A white-pink bead goes once round the outer track per loop, 90° per phase, starting at 12 o'clock and moving clockwise, with four tick marks at the phase boundaries. The flower drifts 45° per loop (8-fold symmetric). |

The pre-rendered videos only cover `idle` and `box`. `listening` and `thinking` exist in the glb only. Adding mp4 loops for them is a few lines in `eve.py` (copy `do_video` with another clip name) if the app needs them.

## Geometry and materials

| | Nodes | Meshes | Unique verts | Triangles drawn |
|---|---|---|---|---|
| eve.glb | 21 | 7 (petal meshes instanced 5× each) | 4,698 | ~15.4k |
| breath.glb | 29 | 11 (petal meshes instanced 8× each) | 4,730 | ~14.2k |

Extensions used: `KHR_materials_emissive_strength`, `KHR_materials_specular`. No Draco. Without it both files are well under budget, and Draco would rule out runtimes that can't decode it (flutter_scene's importer, for one).

The glow is emissive textures (256–512 px PNGs generated by the scripts, in `src/tex/`). Petal base colour is plum #34063F so they still have some form under environment lighting. The aura, haze swirl and ripple rings are alpha-blended flat cards facing glTF +Z (the default camera direction). Keep the camera roughly in front: if a user orbits, the cards show up as flat planes. So no `camera-controls`.

Colours used: night #1D1E2C (background), plum #34063F (petal bases), hot pink #F23598 (petal tips/edges), violets #8A4FFF / #6E29FF / #A36FFF (aura, haze, breath petals, outer ring), white-pink #FFD3EA and blush #FFC9E6 (rings, rim, core, bead, motes), white (core highlight). No green, no lime.

## What the videos have that the glb doesn't

The renders use EEVEE plus a post step (`post.py`): bloom, a soft highlight curve, a white-pink fresnel rim on the petals, brighter petal interiors, coloured area lights and slow firefly motes. None of that exports to glTF, so the real-time version looks flatter and less glowy than the video (compare `src/preview.html` with `review.png`). Same form, same motion, same colours, just no bloom. If the runtime has a bloom pass, turn it on.

## Re-rendering

Needs Blender 4.5 LTS at `D:\dev\blender`, ffmpeg at `D:\dev\tools\ffmpeg-master-latest-win64-gpl`, and OpenEXR + Pillow installed for Blender's Python into `D:\dev\tools\pylibs`:

```bash
D:/dev/blender/4.5/python/bin/python.exe -m pip install --target D:/dev/tools/pylibs OpenEXR Pillow
```

Then, from Git Bash:

```bash
cd D:/therapylink-recovery/design/3d/src
bash build.sh all      # or: eve | breath | hero | sheet
```

About 12 minutes on the RTX 2050. Frames go to `D:\dev\tmp\tl3d` as linear EXR. Nothing is written to C:.

To change colours, edit `PAL` in `src/common.py` (and the hero background in `post.py: hero_bg`) and rerun. Timings live in `CLIPS` (eve.py) and `progress()` (breath.py). `python src/inspect_glb.py eve.glb breath.glb` prints clip names, durations, node and triangle counts. `src/preview.html` shows both glbs in `<model-viewer>` with all clips playing (serve the `3d` folder over http first, e.g. `python -m http.server`).

Checked on this build: both glbs load in `<model-viewer>` 4 (headless Chrome), clips report as `idle, listening, thinking` and `box`, and the animations play.

## Flutter

**(a) Low-end devices, and the default for everyone: pre-rendered video.** Play `eve-idle.mp4` / `breath-box.mp4` with `video_player`, `setLooping(true)`, muted, in a widget whose background is #1D1E2C so the edges disappear. H.264 decodes in hardware on basically every Android phone, so it costs very little CPU or battery. Use the mp4s in the app, not the webm: `video_player` doesn't render VP9 alpha on Android, and iOS doesn't play webm at all. The alpha webms are for the web/HTML mocks (Chrome, Edge, Firefox). ExoPlayer can show a one-frame hitch at the loop point on some phones. If that's visible, pre-concatenate the loop 3–4 times (the files are small) or crossfade two controllers.

For breathing, don't drive the exercise off video playback position alone. Run the 4-4-4-4 timer in Dart and seek the video to match (or restart it on each cycle), so a dropped frame or a paused app can't drift the count.

**(b) High-end devices: real-time glb.** `flutter_scene` (Impeller only, imports glTF at build time through `flutter_scene_importer`) is the closest thing to native. It's still experimental, needs a recent Flutter with Impeller on, and I haven't tested these files in it. What to check first: node TRS animation playback and clip switching (should be fine, that's all these use), alpha-blended cards (aura, swirl, rings) and `KHR_materials_emissive_strength`. If emissive strength is ignored, the petals will look dimmer. Multiply the emissive textures up or bake the strength into them. The lighter-to-build alternative is `model_viewer_plus` (a WebView running `<model-viewer>`), which I did verify, but a WebView costs more memory and startup time than the mp4, so on mobile it's only worth it if Eve needs to react live (e.g. switch `idle` → `listening` → `thinking` while the chat is open).

**(c) Performance, battery, reduced motion.** ~15k triangles and a handful of transparent cards is light for any GPU from the last few years. The cost is that a real-time scene redraws every frame, all the time. Pause rendering (or the video) when Eve is off screen or the app is backgrounded, and cap real-time rendering at 30 fps. Nothing here moves fast, so 30 fps looks the same. When `MediaQuery.of(context).disableAnimations` is true (or the in-app reduced-motion setting is on), show `eve.png` / `breath.png` as static images and nothing else. For the breathing exercise in reduced-motion mode, keep the poster and show the phase as text with the countdown ("Breathe in · 3"). The guidance shouldn't depend on movement.

## Known limits

- The glb has no bloom or rim light. Real-time Eve looks flatter than the video unless the renderer adds bloom.
- The aura, swirl and rings are front-facing cards. Fine for a fixed camera, wrong if users orbit.
- In `<model-viewer>` the default framing includes the aura card, so Eve sits a bit small. Use `camera-orbit="0deg 82deg auto"` and tighten `field-of-view` (around 25–30deg) if she needs to fill the frame.
- `listening` and `thinking` are glb-only (no mp4 yet).
- flutter_scene compatibility is untested.
